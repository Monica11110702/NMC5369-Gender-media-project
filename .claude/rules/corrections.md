# 纠错规则（corrections）

用户指出过的 AI 错误，以及确认后的纠正规则。新条目追加到末尾，编号顺延。
格式：**错误** → **用户指出** → **规则**（以后必须遵守的做法）。

---

### C-01 立绘擅自左右翻转（2026-11-03）
- **错误**：为了让母亲“面向对话框”，把她的半身立绘做了左右镜像。
- **用户指出**：“母亲不需要翻转，直接从左往右移到现在的位置就可以。”
- **规则**：立绘一律使用原图朝向，不做镜像。出场方式是从左侧滑入。verify.py 检查 `flip`。

### C-02 立绘挡住底图里的人物（2026-11-03，出现过两次）
- **错误**：运粮男人（背麻袋，图片很宽）和 Scene 1 的扛粮父亲用原始尺寸显示，挡住了背景里的女孩。
- **用户指出**：“这个人挡住背景那个女生了，我希望让他缩小一点”；“父亲对话框的形象挡住女孩了”。
- **规则**：每加一个对话立绘，都要截图检查它有没有挡住底图里的关键人物，尤其是脸。挡住了就用 `scale` 调小（已有取值：运粮男人 0.68，Scene 1 全部 0.75），汇报时说明。

### C-03 擅自给角色起名（2026-11-03）
- **错误**：剧本里只写了 “a man”，名牌却写成了自己起的 “Grain Carrier”。
- **用户指出**：“名字叫 ‘A Man’ 好了。”
- **规则**：名牌只用剧本中出现的 `Name:`。剧本没有名字时先问用户，不要自己起名。

### C-04 底图区域高度不一致（2026-11-03）
- **错误**：图片序列铺满剧情卡片，而卡片会被里面隐藏的长文字撑高，导致 Scene 1 的底图比序章的更长。
- **用户指出**：“底图的尺寸跟之前不一样了，好像变长了一点，我希望跟原本的保持一致。”
- **规则**：图片序列播放期间卡片高度固定（`.rb-card.filming`）。新增画面后要测量底图高度，和序章保持一致。

### C-05 收尾段落被 Skip 吞掉（2026-11-03）
- **错误**：Skip 会直接跳到最后一句，导致 Scene 1 的共用收尾段落没有显示；测试时用 0.8 秒连点，也没能发现这个问题。
- **用户指出**：“玩家选择 B 选项之后，最后没有出现这一段话……”
- **规则**：Skip 只跳过对话，落在最后一段对话之后的收尾旁白上，收尾期间隐藏 Skip。验证时**必须用自然速度完整走一遍**，不能只靠快速点击测试；在用户能看到的预览窗口里跑自动测试时，要提醒用户那是测试画面。

### C-06 一次性显示全部文字（2026-11-03）
- **错误**：剧情卡片把所有段落同时显示出来。
- **用户指出**：“文字都是同时显现的，看起来有点晕。”
- **规则**：剧情文字一律逐步显现（打字机效果或逐句淡入淡出），文字结束后才出现选项或继续按钮。

### C-08 没发现剧本已更新，差点用旧文字纠正用户（2026-11-05）
- **错误**：检查剧本是否更新时，命令没有输出 “script unchanged”，我却没注意到，仍然拿旧副本对照。用户写的 “kneel at him” 是新剧本的原文，我反而当成笔误，准备改回旧版的 “kneel at his door”。
- **发现方式**：verify.py 直接读取 docx，报出这句不一致。
- **规则**：每个任务开始时都要重新提取剧本，并确认 diff 的结果（没有输出“未变化”就视为有变化）。剧本文字以 verify.py 直接读取 docx 的结果为准，scratchpad 里的副本只作参考。用户引用的文字和我手上的副本不一致时，先重新读一遍剧本，再判断是谁错了。

### C-07 图片铺满整个屏幕（2026-11-03）
- **错误**：开场图片做成了全屏覆盖。
- **用户指出**：“图片不需要覆盖整个画面，只需要覆盖原来这个框内就可以了。”
- **规则**：图片序列只覆盖剧情卡片区域，顶部的 Place/Stage/Time 栏和页头始终保持可见。（唯一例外：红嫁衣开场图按用户要求全屏，见 D-F16。）

### C-09 素材已到位却问用户要不要补（2026-11-06）
- **错误**：Scene 6 汇报时问“要不要补一张祠堂老妇人的立绘”，以及要不要给 Scene 5 换嫁衣立绘，但文件夹里已经有 `祠堂老妇人_全身透明立绘.png` 和嫁衣立绘。开工时查过素材，汇报前没有再查一次。
- **用户指出**：“女主的红色立绘已经有了，老妇人的也是。”
- **规则**：用户在同时往文件夹里放素材。说“缺素材”或问“要不要补”之前，先重新列一遍素材文件夹（`find . -newermt …`）；已有合适的素材就直接用，再汇报。

### C-10 没有核实就说仓库是私有的（2026-11-06）
- **错误**：上传后汇报时写“私有仓库”，只是沿用旧记录。实际上仓库已经是公开的，还开了 GitHub Pages。报告成功时也只查了 git，没看网站有没有发布成功。
- **发现方式**：用户贴出 Actions 的提示后，我查 GitHub API 才发现。
- **规则**：上传后要查仓库的公开状态和 Actions 运行结果，线上网站真的更新了才能说发布成功。
